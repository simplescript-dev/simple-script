## 核心原则 (Principles)

1. **走完整 JDBC 4.3 §10.2 + §13.x CallableStatement spec ≥30 method**:不简化、不 stub 关键 method、不"够用就行"(用户对话锁不接次优 / workaround / 节省路径)
2. **复用 D157 ParameterMetaData mode 升级路径**:升级 MysqlParameterMetaData.getParameterMode 从静态 parameterModeIn 改为 paramDirections array 反射 — D157 §A.2 H6 mode 字面值常量 已落地(parameterModeIn=1 / parameterModeInOut=2 / parameterModeOut=4 / parameterModeUnknown=0),本 D 仅扩 reflection 路径不重新发明常量
3. **复用 D154 MysqlPreparedStatement binary protocol path**:MysqlCallableStatement extends MysqlPreparedStatement 直接继承 prepare / execute / fetchRow / RESULT_SET round-trip 路径,setXxx INOUT 路径完全复用 PreparedStatement bind buffer — 不重新发明 wire-level binary protocol parameter binding
4. **binary protocol parameter direction byte 路径首次实现**:MySQL 5.7+/8.0 binary protocol 不显式区分 IN/OUT/INOUT(server-side 不读取 direction byte) — driver-side emulate(同 Connector/J `CallableStatement` 范式),paramDirections array 仅在 client 侧用于 OUT 参数 ResultSet round-trip 收值与 getParameterMode 真值反射
5. **RESULT_SET 多 round-trip 收 OUT 参数返值**:MySQL stored procedure CALL 的 server 行为是返 N+1 个 ResultSet — 前 N 个为 procedure body 内 SELECT 输出,最后 1 个为 OUT/INOUT 参数 1-row ResultSet(MySQL Native Protocol §15.7.4 SERVER_MORE_RESULTS_EXISTS bit 8)— driver 侧 drain 至最后 ResultSet 取 OUT 值 — H2 实证锚
6. **D135-D157 SQL 主线范式延续**:Phase 计划独立 commit + Status 收关 + hash 回填 + next_prompt 自闭环 + §A.2 隐藏假设 + §A.3 废案 + §Followup
7. **不简化关键 method**(D147 Phase 5 7-shape integration_test 范式 + D154 §F7 12 driver class round-trip + D155 Phase 4 10 case docker probe-skip + D156 Phase 4 10 case docker probe-skip + D157 Phase 3 9 case docker probe-skip 范式延续)— integration_test e2e 必含 wire 端真值实证
8. **MysqlCallableStatement single-instance,paramDirections array snapshot 不持额外协议状态**:Class 仅持 paramDirections: Array<int>(num_params 长度,registerOutParameter 时填值)+ 继承 MysqlPreparedStatement 既有协议字段 — 不持额外 wire-level cache,close() 走 PreparedStatement.close() 链式 — H5 RC cycle 显式 break
9. **不引入新协议解析层**:复用 ColumnDef41 + binary protocol path(D157 §核心原则 9 同款 scope 减项)— prepareCall 走 COM_STMT_PREPARE 同路径 server 默认返 num_params + ParameterDef block,无新 packet 解析需求
