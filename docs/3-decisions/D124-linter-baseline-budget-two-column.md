## 第一性问题

D097 linter baseline (`tools/linter_baseline.txt`) 当前为单列格式,每行 `metric=value`。该格式让单个数值同时承担两个角色:

1. **历史证据**(真实 AST 计数) — record 时由 linter 从当前源码实测写入,下轮 gate 比对
2. **gate 阈值**(当轮不许超过) — `cur > baseline + tol` → REGRESSION 阻断(累计组 tol=baseline/200,结构组 tol=0)

在**非扩容轮**(refactor / bugfix / 新测试),两角色一致:真实状态即阈值,D097 §累积方向严禁更新 的单调下压规则合理。在**扩容轮**(反射路径形态升级,如 D121 R1-A AnnotationMeta.args Array→Map),两角色**冲突**:

- 累计组指标(M1/M2/M5/N2)物理下限随 Meta 形态线性升高(新 kind 分支 + 新 Map slot + 新调用边),**新证据**必然 > 旧值
- 但若 gate 阈值随动,D097 §累积方向严禁更新 的"机械 guard"即失效 — 用户手工改 baseline.txt 可绕过 `record` 校验

D121 Execute 2 R1-A 暴露此冲突,被迫走**申报态 workaround**(D121 L675-677):commit 带 GATE BLOCKED 证据 + D 文档 §扩容申报段承载 gate 放行,linter 输出 BLOCKED 但 commit 不阻。此 workaround 违反 D097 §Gate 行为 L62-63 "仅此两种终态,无中间" 契约,且依赖人读 D 文档区分"真 REGRESSION vs 申报态",**等同让 gate 从机械守护退化成软约束**。

**根因**:单列数值无法同时表达"历史证据(可升 — 因真实状态确实升了)" + "gate 阈值(严格 ≤)"。物理分离两角色 = 2 列制:

- `baseline_value` = 真实 AST 计数(下压规则不变,单调下降;扩容后 Execute 回填)
- `budget_max` = gate 阈值(扩容申报驱动上移,非扩容轮 `budget_max == baseline_value`)

非扩容轮两列同值,gate 行为等同 D097 严格契约;扩容轮 `budget_max > baseline_value` 显式记录扩容预算,commit trail 可回溯每次 bump 指向的 D 文档 §扩容申报 锚点。

## 决策 1:数据格式

### 1.1 文件格式

`tools/linter_baseline.txt` 升为 2 列,每行:

```
<metric>=<baseline_value>:<budget_max>
```

举例(对齐 D121 §扩容申报 实测目标):

```
# auto-generated by tools/reflection_health_linter.ss — do not edit
M1=5134:5168
M2=76126:76617
M3a=12122:12122
M3b=1879:1879
M4=3011:3011
M5=1750:1765
M6=32:32
M7a=27:27
M7b=676:676
N1=34:34
N2=380630:383085
N3=517080:517080
N4=321:321
N5=0:0
F1:bootstrap/parse/parser.ss=813:813
F1:bootstrap/main.ss=630:630
...
```

### 1.2 选型对比

| 候选 | 示例 | 优 | 劣 |
|---|---|---|---|
| **A. 等号 + 冒号(选定)** | `M1=5134:5168` | 最小改动:`parseKV(line, "M1=")` 前缀解析只需 split 冒号;等号右侧语义向下兼容 | 视觉紧凑略欠 |
| B. 空格分隔 | `M1 5134 5168` | 可读性高 | 现有 prefix 字符串 `"M1="` 需全改为 `"M1 "`; `parseKV` 主逻辑重写 |
| C. JSON 结构 | `{"M1":{"baseline":5134,"budget":5168}}` | 未来扩字段方便 | SS 当前无 JSON lexer,手写解析 ~50 行;违 P13 "extract only when justified" |

**锁定 A**:改动面最小,`parseKV(line, "M1=")` 仅需把 "parseInt(rest)" 升为 "split `:` → (baseline_value, budget_max)"。等号左侧(metric 前缀)零改动,`readBaselineVal` 接口重命名为 `readBaselineRow` 返回二元组即可。

### 1.3 F1 行数 baseline 同步升 2 列

`F1:<path>=<lines>` 条目同升:`F1:<path>=<baseline_lines>:<budget_lines>`。规则对齐 D102 §2.1 R1-R4(`feedback_f1_gate_semantic` 配套):

- **R1**(S1, >600 baseline 有):`baseline_value` 单调下压;`budget_max` 默认同 baseline_value,扩容极少见(拆文件是首选路径,bump F1 budget 需 D 文档显式说明"为何不拆文件")
- **R2**(S4, ≤600 baseline 无):不入库(R4 graduate 逻辑不变,两列同时不写)
- **R3**(S3, >600 baseline 无):REGRESSION 阻断(新文件走拆文件路径,零扩容通道)
- **R4**(record):下压时两列同降(若原本同值) / 若分离(扩容后)baseline_value 下压 budget_max 保持或按 CLI 下压

### 1.4 历史单列兼容

过渡期 `readBaselineRow(prefix)` 对旧单列行向下兼容:

- 行含冒号 → 解析两 int(2 列新格式)
- 行无冒号 → 视作 `baseline_value == budget_max`(legacy 单列)
- 异常格式(多冒号 / 非数字)→ 报错退出,不自动修复(见决策 3.3)

Execute 轮首次 `record` 命令自动把文件升到 2 列格式,过渡期限 1 commit 即完。

## 决策 2:Gate 条件

### 2.1 PASS 条件升级

旧 gate(D097 L54-63,`reflection_health_linter.ss:466-485`):
- `cur ≤ baseline` → PASS
- `cur > baseline + tol` → REGRESSION 阻断(累计组 tol=baseline/200,结构组 tol=0)

新 gate:**`cur ≤ budget_max → PASS;cur > budget_max → BLOCKED`**。四终态重定义:

| 终态 | 条件 | 含义 | record 行为 |
|---|---|---|---|
| **PROGRESS** | `cur < baseline_value` | 真实下压 | record 把 baseline_value 降至 cur;budget_max 同降到 cur(若原本两列同值)或保持不变(若 budget_max 高于 baseline_value,即扩容历史高水位 stamp) |
| **OK** | `cur == baseline_value` | 恰好基线 | 无变化 |
| **DRIFT** | `baseline_value < cur ≤ budget_max` | 扩容预算内浮动 | gate 不阻;record 允许升 `baseline_value` 到 cur(扩容 Execute 完成,新真实 AST 状态 ≤ budget_max 是合法的"预算内消耗"),`budget_max` 保持 stamp 不降;与 §决策 3.2 "Execute 后另一次 record 把 baseline_value 同步到新真实 cur" 自洽 |
| **REGRESSION** | `cur > budget_max` | gate 阻断 | record 拒;要么回退 cur,要么走 `bump` CLI 升 budget_max |

**旧 `tol = baseline / 200` 机制废除** — 2 列制下"tol" 由 `budget_max - baseline_value` 显式表达,不再隐含比例。累计组(M1/M2/M3a/M5/N1/N2)与结构组(M3b/M4/M6/M7a/M7b/N3/N4/N5)在 gate 条件上**统一**,差异全落到 "何时允许 bump" 的策略判断(反射扩容协议,`feedback_reflection_expansion_protocol` §How to apply 1 三选一)。

### 2.2 budget_max 单调性

- **上移**:必须经 `bump` CLI(见决策 3.2),禁止手工编辑 `tools/linter_baseline.txt`
- **下压**:随 `record` 一起下压,规则见决策 2.1 PROGRESS 行
- **commit trail**:每次 `bump` 必指向某 D 文档 `§扩容申报` 锚点,可 grep 回溯每次扩容理由

### 2.3 不可伪造性保证(强化 D097)

2 列制**加强**而非弱化 D097 §不可伪造:

1. **baseline_value 单调下压**规则不变(D097 契约完整保留)
2. **budget_max 上移**必带 CLI flag 指向 D 文档 §扩容申报,手工 edit baseline.txt 不触发 CLI trail → 下轮 `record` 发现格式异常拒记录(决策 3.3 校验)
3. **gate 阈值(budget_max)**从"累积扩容历史"演化,git log `tools/linter_baseline.txt` 可追溯每次 bump 指向的 D 文档

### 2.4 F1 行数 gate 语义(对齐 D102)

F1 R1 语义维持 D102 §2.1 + `feedback_f1_gate_semantic`:`cur > F1 budget_max` → BLOCKED。F1 扩容极罕见,正常路径走拆文件(D102 §规则 2.4);`bump F1:<path> <new>` CLI 需 D 文档显式说明"为何不拆文件走扩容路径"。实际运行中 R1 14 文件预计全走下压,`budget_max == baseline_value` 长期稳定。

### 3.2 新 CLI 子命令:`bump`

```
bin/ss run tools/reflection_health_linter.ss bump <metric> <new_budget_max> <doc_anchor>
```

参数:
- `<metric>`:指标名(`M1`/`M2`/.../`N5` 或 `F1:<path>`)
- `<new_budget_max>`:新预算上限(必须 ≥ 当前 budget_max,且 ≥ cur)
- `<doc_anchor>`:D 文档段落锚点(形如 `D121#扩容申报`),落入 baseline.txt 注释行作为 audit trail

校验(拒绝场景):
- `new_budget_max < cur` → 拒:申报不够用(应先 bump 到 ≥cur 再操作)
- `new_budget_max < old_budget_max` → 拒:bump 只上不下(下压走 record)
- `<doc_anchor>` 文件不存在 → 拒
- 锚点 grep 命中不到该段落 → 拒(强制文档落段)
- `grep -c "§扩容申报\|扩容申报" <D文档>` == 0 → 拒(防乱填锚)

写入行为:
- 修改对应 metric 行的 budget_max(第二个数字)
- baseline_value 不改(真实 AST 状态未变,bump 只是"预留扩容预算"/"Execute 后另一次 record 把 baseline_value 同步到新真实 cur")
- 注释行追加 audit trail:`# bump M1 5134→5168 trail=D121#扩容申报 date=2026-04-22`

### 3.3 baseline.txt 格式校验

`readBaselineRow` 读文件时:
- 单列行(无冒号)→ 视作 legacy(`baseline == budget`)
- 双列行(恰一个冒号)→ 解析两 int
- 异常格式(多冒号 / 非数字 / 空值)→ 报错退出,**不自动修复**(防手工 edit 绕 CLI)
- `record` / `bump` 两入口写入时才升级格式,读入口只校验不修复

## 反模式 / 正模式

### ❌ 反模式
- 手工编辑 `tools/linter_baseline.txt`(破 audit trail + 破单调 guard + 破 CLI 校验 3.3)
- 不起 D 文档 §扩容申报段就 `bump`(无 trail,`bump` CLI 拒)
- `bump` 下移 budget_max(只上不下规则;下压走 `record`)
- 扩容轮 `record` 让 baseline_value 升位(扩容规则在 `bump`,不在 `record`)
- 单列 tol=baseline/200 机制残留在 2 列制里(两 tol 并存混乱,本决策废)
- 把 F1 bump 当默认路径(违 D102 §规则 2.4 拆文件优先)

### ✅ 正模式
- 2 列物理分离:`baseline_value`=证据(下压)+ `budget_max`=阈值(扩容申报上移)
- 两 CLI 两路径:`record` refactor 下压 / `bump` 扩容申报
- `bump` 必带 D 文档锚,commit trail 可 grep 回溯每次扩容理由
- DRIFT 态显式命名(`baseline_value < cur ≤ budget_max`),预算内浮动 gate 不阻但 record 不写
- 非扩容轮两列同值,gate 行为等同 D097 严格契约(零损耗向下兼容)
- legacy 单列回退一次性过渡,首次 record 自动升格式
