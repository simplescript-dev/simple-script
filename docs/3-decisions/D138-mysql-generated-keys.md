## 核心目标 (Goal)

- **为什么**:`INSERT INTO user(name, age) VALUES ('Alice', 30)` 后业务必需取 auto-increment id(几乎所有业务 INSERT 都需要)。当前 MySQL 协议层 `parseOkPacketAffectedRows`(query.ss:75)只读 affected rows,`last_insert_id` 字段在 `query.ss:70` 注释 `lenenc int: last_insert_id (skip)` 显式抛弃。`MysqlStatement.executeUpdate` / `MysqlPreparedStatement.executeUpdate` 同样不存 lastInsertId。JDBC `Statement.getGeneratedKeys()` / Spring `KeyHolder` 接口当前完全缺失。**业务影响**:用户写 INSERT 后无法链 SELECT MAX(id) 之外的安全方式拿 id;ORM/Repository 层 `save(entity)` 后无法回填 `entity.id`,JpaRepository 风格断链。

- **是什么**:走**完整 JDBC 4.3 spec**(不走 SS 轻量 workaround)+ **Spring KeyHolder 标准**:
  - **协议层**:`class OkPacket { affectedRows: int, lastInsertId: int, statusFlags: int, warnings: int }` 完整 parse + `parseOkPacket(payload, payloadLen): OkPacket` + `readUpdateResultPacket(fd): OkPacket`(`readUpdateResult(fd): int` 保留作 thin wrapper 向后兼容)
  - **JDBC 接口扩展**(`lib/java/sql.ss`):`interface Statement` 加 `getGeneratedKeys(): ResultSet` + `getLastInsertId(): int` + 常量 `RETURN_GENERATED_KEYS = 1` / `NO_GENERATED_KEYS = 2`;`interface PreparedStatement` 同位 2 method;`interface Connection` 加 `prepareStatement(sql: string, autoGeneratedKeys: int): PreparedStatement` 重载
  - **新 ResultSet 实现**:`class GeneratedKeyResultSet : ResultSet`(单行单列,列名 `"GENERATED_KEY"` — MySQL Connector/J 标准)— 包装 lastInsertId 走 ResultSet 标准接口
  - **MySQL 实现扩**:MysqlStatement / MysqlPreparedStatement 加 `lastInsertId: int` 字段;executeUpdate 时存;`getGeneratedKeys()` 返 GeneratedKeyResultSet;`getLastInsertId()` 返 字段
  - **Spring KeyHolder**(`lib/spring/jdbc.ss`):`interface KeyHolder { getKey(): int; getKeyAsLong(): int; getKeys(): Map<string,int>; getKeyList(): Array<Map<string,int>> }` + `class GeneratedKeyHolder : KeyHolder` impl + `JdbcTemplate.update(sql, setter, keyHolder: KeyHolder): int` 重载

- **单一判据**:6 形态 `tests/d138_generated_keys/integration_test.ss` 全 GREEN — (1) INSERT 单行 + `stmt.getLastInsertId()` 直取 / (2) INSERT 单行 + `stmt.getGeneratedKeys()` ResultSet 走 spec / (3) INSERT 单行 + `JdbcTemplate.update(sql, setter, keyHolder)` + `keyHolder.getKey()` Spring 标准 / (4) INSERT 多行 `VALUES (...),(...),(...)` + getLastInsertId 返首 id(MySQL 协议规定)/ (5) transaction 中 INSERT + commit 后 id 持久 / (6) ERR packet INSERT 失败 + getLastInsertId 返 0 防御。

## 核心原则 (Principles)

1. **完整 JDBC 4.3 spec,不裁剪**:`Statement.getGeneratedKeys(): ResultSet` 走 ResultSet 标准接口(不走 SS 轻量 `int` 直返)— ResultSet 是 spec 唯一返路,即使包装单 long 也按 spec 标 `"GENERATED_KEY"` 列名(MySQL Connector/J 标准)
2. **Spring KeyHolder 标准,不裁剪**:`interface KeyHolder` 4 method 全实现(getKey / getKeyAsLong / getKeys / getKeyList);`GeneratedKeyHolder` 内部 `keyList: Array<Map<string,int>>` 完整结构(为 multi-row INSERT + multi-column generated keys 留扩展位,SS 当前限 int 类型)
3. **OK packet 全字段 parse,无 skip**:`class OkPacket { affectedRows, lastInsertId, statusFlags, warnings }` 4 字段全保留;`info string` 字段(SESSION_TRACK 路径)留 §Followup F1
4. **接口层 trap,非数据层 patch**:lastInsertId 信息源单点(`OkPacket.lastInsertId` 字段),所有消费者(MysqlStatement / MysqlPreparedStatement / GeneratedKeyResultSet / KeyHolder)走单一信息源回填,不在多个调用方零散补 fallback
5. **MySQL 协议层 readUpdateResult 向后兼容**:`readUpdateResult(fd): int` 保留 thin wrapper 调 `readUpdateResultPacket` 取 affectedRows 字段(commit/rollback/setAutoCommit 等内部消费方零破坏)
6. **JDBC `RETURN_GENERATED_KEYS` 常量 + autoGeneratedKeys 参数**:`Connection.prepareStatement(sql, autoGeneratedKeys)` 重载完整;MySQL 协议默认所有 INSERT 都返 lastInsertId(autoGeneratedKeys 对 MySQL 等价 no-op),但保 JDBC spec 一致 — 未来切 PostgreSQL / SQLite 时此参数有意义
7. **依赖路径 + 编译器扩允许**:依赖 D025 interface dispatch + D136 prepared statement 已落地路径;**Phase 1.5 编译器扩 interface method overload by arity**(D138 §A.2 H4 假设破裂回路 — 2026-04-28 Phase 2 实测 `bootstrap/gen/gen_iface.ss:16/31` byName key + `emittedDispatchers` byName 去重 → SS interface 不支持 method overload by arity;class method 已支持 paramSig mangle 但 interface dispatcher 未升级);用户对话锁"最优最佳 / 不 workaround / 不节省"+ CLAUDE.md §Root Cause 第一法则"编译器限制是 bug,不是边界条件"+ "真做不到就停手不做,绝不接受次优"— 故本 D 范围允许编译器扩(原 Phase 0 落档时擅自加的"不修编译器"硬约束 2026-04-28 推翻)
8. **per-call Connection 简化继承**:JdbcTemplate.update(sql, setter, keyHolder) 内部 prepareStatement → setter → executeUpdate → getGeneratedKeys → fill keyHolder → close,per-call Connection lifecycle 与 D137 同(HikariCP D125+ 是另一 sub-D)
9. **6 形态测试覆盖 — 不偷工减料**:Phase 4 测试覆盖 §核心目标 6 判据全形态,含 multi-row INSERT 首 id + transaction 持久 + ERR packet 防御 + Spring KeyHolder 完整 path
10. **Phase 计划独立 commit**:Phase 0-5 独立 commit;Phase 0 D 文档落档不打包 Phase 1+ 实施(D135/D136/D137/D141 范式)
11. **VCM 六验全跑**:bootstrap 三阶段固定点(本 D 不改编译器但 lib/ 改触发 build cache)+ tests/d134_mysql / d135_caching_sha2 / d136_prepared_statement baseline 不降 + tests/d141-d144 反推机制 baseline 不破 + reflection_health GATE PASS + d_doc_index PASS

## 6. Constraints

### 硬约束

- **完整 JDBC 4.3 + Spring KeyHolder 标准**(用户对话锁:不裁剪 / 不 workaround / 不简化)
- 不动 D025 interface dispatch 契约
- 不动 D134 wire protocol 本体(OK packet read 路径不破)
- 不动 D136 prepared statement 本体(executeUpdate 调用方升级,本体不重写)
- 不动 D137 JdbcTemplate 5 method baseline(向后兼容,加重载不改既有)
- Phase 1.5 编译器扩 interface method overload by arity(D138 §A.2 H4 假设破裂回路 + §Root Cause 第一法则);其他不动 D025 interface dispatch 契约 / D134 wire protocol 本体 / D136 prepared statement 本体 / D137 JdbcTemplate 5 method baseline
- bootstrap 改不许超过 1000 LOC delta — 实际预估 ~580 LOC(Phase 1.5 编译器 ~150 + Phase 1 query.ss + Phase 2 jdbc.ss + prepared.ss + sql.ss + Phase 3 spring/jdbc.ss + Phase 4 测试)

### 软约束

- 优先编译期硬错(JDBC `Connection.prepareStatement(sql, NO_GENERATED_KEYS)` 时 stmt.getGeneratedKeys() 返空 ResultSet,not exception)
- multi-column generated keys 当前 MySQL 限 AUTO_INCREMENT 单列 — KeyHolder.getKeys() 返单 key Map(扩展位留 spec)
- multi-row INSERT lastInsertId 是首 id(MySQL 协议规定;若用户期望全 id 走 SELECT WHERE id >= first AND id < first + affectedRows,业务侧自处理)

### 风险锚(R1-R5)

| # | 风险 | 描述 | mitigation |
|---|---|---|---|
| R1 | OkPacket 字段顺序与 lenenc int 长度变长 | OK packet `affected_rows` + `last_insert_id` 都是 lenenc int(1/3/4/9 字节变长),offset 推进必须用 `lengthEncodedIntSize` 计算 | Phase 1 实测 docker MySQL 返多种 affected_rows / last_insert_id 组合(0/1/255/65535/auto-increment 大值)边界 |
| R2 | readUpdateResult 向后兼容 thin wrapper 性能 | 调用方多(commit/rollback/setAutoCommit + d134/d135 测试),包装 OkPacket 后 thin wrapper 取字段是否 alloc Map | OkPacket 是 class 不是 Map,字段直接 GEP 访问,无 alloc 开销 |
