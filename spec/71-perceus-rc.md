# Perceus Reference Counting + Field-Level Immutability

## Overview

SimpleScript uses Perceus-style reference counting for deterministic memory management. Objects are heap-allocated with reference counts. Assignment (`let b = a`) creates a shared reference (pointer copy + rc_inc). Explicit `.deepClone()` / `.shallowClone()` methods create independent copies. Field-level `const` controls mutability at the field granularity.

**Design goals:**
1. Assignment defaults to shared reference (same object)
2. Immutability controlled at field level via `const` modifier
3. Perceus RC analysis enables in-place mutation when rc==1
4. No GC, no cyclic references, no weak/unsafe/lifetime syntax exposed to users

**References:**
- [Perceus: Garbage Free Reference Counting with Reuse (MSR, 2021)](https://www.microsoft.com/en-us/research/publication/perceus-garbage-free-reference-counting-with-reuse/)
- [Koka Language](https://koka-lang.github.io/) — Perceus reference implementation
- [Frame Limited Reuse (Lorenzen et al., 2023)](https://www.microsoft.com/en-us/research/publication/frame-limited-reuse-with-reference-counting/)

## 1. User-Facing Syntax

### 1.1 Class Definition with Field-Level const

```
class Player {
    const name: string     // immutable: set only at construction
    health: int            // mutable: can be reassigned anytime
    x: int
    y: int
}
```

- No `const` modifier: mutable field, assignable after construction
- `const` modifier: immutable field, compiler rejects any post-construction assignment
- Field declarations are constructor parameters: `new Player("Alice", 100, 0, 0)`
- Named parameter construction supported: `new Player(name: "Alice", health: 100, x: 0, y: 0)`

### 1.2 Assignment Semantics

**Assignment defaults to shared reference. `.deepClone()` / `.shallowClone()` create independent copies.**

```
let a = new Player("Alice", 100, 0, 0)
let b = a                  // b and a point to same object
let c = a.deepClone()      // c is fully independent copy
let d = a.shallowClone()   // d is new object, internal refs shared

a.health -= 20
print(b.health)            // 80 — same object, change visible
print(c.health)            // 100 — independent copy, unaffected
```

Type-specific behavior:
- **Class instances** (heap): pointer copy + rc_inc. Mutations visible through all references.
- **string** (immutable): shared reference. `ss_string_concat` returns new string, old unaffected.
- **int / double / bool** (stack): value copy. No RC involvement.
- **List / Map / Set** (heap): pointer copy + rc_inc. Mutations visible through all references.

### 1.3 Field Assignment

```
let hero = new Player("Alice", 100, 0, 0)
hero.health -= 25          // OK: mutable field
hero.x = 10                // OK: mutable field
hero.name = "Bob"          // COMPILE ERROR: name is const field
```

Nested field assignment:
```
hero.weapon.damage += 10       // OK if Weapon.damage is mutable
hero.weapon.name = "Axe"       // ERROR if Weapon.name is const
hero.weapon = new Weapon(...)   // OK if Player.weapon is not const
```

### 1.4 let vs const Binding

```
let hero = new Player("Alice", 100, 0, 0)
hero.health -= 25                         // OK: mutable field
hero = new Player("Bob", 80, 1, 1)       // OK: let allows rebinding

const hero2 = new Player("Alice", 100, 0, 0)
hero2.health -= 25                        // OK: mutable field still writable
hero2.name = "Bob"                        // ERROR: const field
hero2 = new Player("Bob", 80, 1, 1)      // ERROR: const binding, no rebinding
```

Two independent layers:

| Layer | Controls | let | const |
|-------|----------|-----|-------|
| Binding (let/const) | Can rebind to another object? | Yes | No |
| Field (const modifier) | Can modify this field's value? | Per field declaration | Per field declaration |

### 1.5 Function Parameters

Parameters default to shared reference. Modifications inside function are visible to caller:

```
function damage(p: Player, amount: int) {
    p.health -= amount
}

function main() {
    let hero = new Player("Alice", 100, 0, 0)
    damage(hero, 25)
    print(hero.health)   // 75 — modification visible
}
```

To prevent modification, pass `.deepClone()` or `.shallowClone()`:
```
damage(hero.deepClone(), 25)   // hero unaffected
```

### 1.6 Clone Methods

No `.clone()` alias. Users must explicitly choose:

**`.deepClone()`** — recursive copy, fully independent:
- int/double/bool: value copy
- const fields, string (immutable types): rc_inc only (safe to share)
- Mutable reference-type fields: recursive `.deepClone()`
- New object rc = 1

**`.shallowClone()`** — first-layer copy, internal refs shared:
- All fields copied by value/pointer
- Reference-type fields: rc_inc (shared, not cloned)
- New object rc = 1

Both auto-generated by compiler. Users can override:
```
class Player {
    const name: string
    health: int
    weapon: Weapon

    function deepClone(): Player {
        return new Player(this.name, this.health, this.weapon.deepClone())
    }
}
```

### 1.7 Collection Types

**Phase 1:**
- `List<T>` — mutable ordered collection (renamed from Array)
- `Map<K, V>` — mutable key-value collection (existing)
- `Set<T>` — mutable unique collection (new, Map wrapper)

**Phase 2+:**
- `FixedList<T>` — immutable list (no add/remove/replace)
- `FixedMap<K, V>` — immutable map
- `FixedSet<T>` — immutable set

Semantics: `Fixed*` means collection structure is fixed. Element internal mutability still depends on element's own field `const` declarations.

```
let items: List<Player> = [hero1, hero2]
items.push(hero3)          // OK: List is mutable
items[0].health -= 20      // OK: Player.health is mutable
items[0].name = "Bob"      // ERROR: Player.name is const

let frozen: FixedList<Player> = [hero1, hero2]
frozen.push(hero3)         // ERROR: FixedList cannot add
frozen[0].health -= 20     // OK: Player.health is mutable
```

## 2. Compiler Architecture

### 2.1 Pipeline

```
Source (.ss)
  |
  v
Lexer --> Tokens
  |
  v
Parser --> AST
  |
  v
Type Checker
  |
  v
Field const check (reject const field assignment)
  |
  v
AST --> Perceus IR (PIR) lowering
  |
  v
PIR Optimization Passes (5 passes)
  |
  v
PIR --> LLVM IR Codegen
  |
  v
LLVM (llc-18) --> Object file
  |
  v
musl-gcc (+ mimalloc) --> Static binary
```

### 2.2 Object Layout

Every class instance has RC at offset 0 and TypeInfo pointer at offset 1:

```llvm
%Player = type {
    i32,              ; rc (offset 0)
    %TypeInfo*,       ; type_info (offset 1)
    ptr,              ; name: string (offset 2, const field)
    i64,              ; health: int (offset 3)
    i64,              ; x: int (offset 4)
    i64               ; y: int (offset 5)
}
```

RC operations use bitcast to generic header:
```llvm
%RcHeader = type { i32, %TypeInfo* }

; Usage:
%hdr = bitcast %Player* %p to %RcHeader*
call void @ss_retain(%RcHeader* %hdr)
```

### 2.3 TypeInfo

Compiler generates one global TypeInfo constant per class:

```llvm
%TypeInfo = type {
    void (%RcHeader*)*,         ; drop function pointer
    i8* (%RcHeader*, i64)*,     ; deep_clone function pointer
    i8* (%RcHeader*, i64)*,     ; shallow_clone function pointer
    i64,                         ; object size (bytes)
    ptr                          ; type name string
}

@Player_type_info = constant %TypeInfo {
    void (%RcHeader*)* @ss_drop_Player,
    i8* (%RcHeader*, i64)* @ss_deep_clone_Player,
    i8* (%RcHeader*, i64)* @ss_shallow_clone_Player,
    i64 48,
    ptr @.str.Player
}
```

Phase 1: TypeInfo contains only drop + clone dispatch (no method vtable).
Phase 4: TypeInfo extended with method vtable for interface dispatch.

### 2.4 Runtime Functions

All prefixed with `ss_`:

| Function | Signature | Purpose |
|----------|-----------|---------|
| `ss_retain` | `void (%RcHeader*)` | rc + 1 |
| `ss_release` | `void (%RcHeader*)` | rc - 1; if 0, call drop via TypeInfo |
| `ss_is_unique` | `i1 (%RcHeader*)` | return rc == 1 |
| `ss_alloc` | `i8* (i64)` | allocate memory, rc initialized to 1 |
| `ss_dealloc` | `void (i8*)` | free memory |
| `ss_shallow_copy` | `i8* (i8*, i64)` | byte copy, new object rc = 1 |

Per-class (compiler-generated):
| Function | Purpose |
|----------|---------|
| `ss_drop_ClassName` | rc_dec all ref-type fields, then ss_dealloc |
| `ss_deep_clone_ClassName` | recursive deep clone |
| `ss_shallow_clone_ClassName` | shallow byte copy + rc_inc ref fields |

`ss_release` is fully generic — finds drop function via TypeInfo vtable:
```llvm
define void @ss_release(%RcHeader* %obj) {
    %rc_ptr = getelementptr %RcHeader, %RcHeader* %obj, i32 0, i32 0
    %rc = load i32, i32* %rc_ptr
    %rc_new = sub i32 %rc, 1
    store i32 %rc_new, i32* %rc_ptr
    %is_zero = icmp eq i32 %rc_new, 0
    br i1 %is_zero, label %drop, label %done
drop:
    %ti_ptr = getelementptr %RcHeader, %RcHeader* %obj, i32 0, i32 1
    %ti = load %TypeInfo*, %TypeInfo** %ti_ptr
    %drop_fn_ptr = getelementptr %TypeInfo, %TypeInfo* %ti, i32 0, i32 0
    %drop_fn = load void (%RcHeader*)*, void (%RcHeader*)** %drop_fn_ptr
    call void %drop_fn(%RcHeader* %obj)
    br label %done
done:
    ret void
}
```

### 2.5 Memory Allocator

Phase 1 introduces mimalloc (replaces musl calloc for object allocation):
- Required for Perceus REUSE optimization (LIFO free-list behavior)
- Integration: compile `mimalloc/src/static.c`, link statically
- Size overhead: ~50-100KB
- Compatible with musl libc

```c
// ss_alloc / ss_dealloc backed by mimalloc
void* ss_alloc(size_t size) { return mi_calloc(1, size); }
void  ss_dealloc(void* ptr) { mi_free(ptr); }
```

## 3. Perceus IR (PIR)

### 3.1 Purpose

Intermediate representation between AST and LLVM IR. All RC operations and memory operations are expressed at this level. Optimization passes transform PIR before LLVM IR codegen.

### 3.2 Data Representation

PIR nodes use the same Map-based system as AST nodes (bootstrap compatibility):

| Field | Usage |
|-------|-------|
| `pirKind` | Instruction type: `"RC_INC"`, `"ALLOC"`, `"FIELD_SET"`, etc. |
| `pirStr1` | Primary operand (variable name, function name) |
| `pirStr2` | Secondary operand (type name, field name, result var) |
| `pirStr3` | Tertiary operand (result var for FIELD_GET, type for REUSE) |
| `pirInt1` | Node ID operand (value node for FIELD_SET) |
| `pirList` | Argument list (comma-separated node IDs) |

A function's PIR is a list of node IDs (equivalent to `Vec<PirOp>`).

### 3.3 Instruction Set

| Instruction | Fields | Semantics |
|-------------|--------|-----------|
| `RC_INC` | str1=var | ss_retain |
| `RC_DEC` | str1=var | ss_release (drop if rc→0) |
| `RC_IS_UNIQUE` | str1=var, str2=result | ss_is_unique |
| `ALLOC` | str1=result, str2=type, list=args | ss_alloc + init rc=1 + fill TypeInfo |
| `MOVE` | str1=src, str2=dst | ownership transfer, no RC ops |
| `DEEP_CLONE` | str1=src, str2=dst | recursive clone |
| `SHALLOW_CLONE` | str1=src, str2=dst | shallow copy + rc_inc fields |
| `DROP` | str1=var | call ss_drop_XXX + ss_dealloc |
| `REUSE` | str1=old, str2=new, str3=type | reuse old's memory for new (skip dealloc+alloc) |
| `FIELD_SET` | str1=obj, str2=field, int1=valNode | set field (old val RC_DEC + new val RC_INC) |
| `FIELD_GET` | str1=obj, str2=field, str3=result | read field |
| `CALL` | str1=func, str2=result, list=args | function call (args tagged mutated/readonly) |

### 3.4 Optimization Passes (executed in order)

**Pass 1: Liveness Analysis**
- Mark last-use point for each variable
- Insert RC_DEC after last use

**Pass 2: Move Analysis**
- If variable has RC_INC followed by exactly one RC_DEC with no other uses between → replace with MOVE
- Eliminates redundant retain/release pairs
- Typical: function parameter passing where caller doesn't use variable after call

**Pass 3: Uniqueness Analysis**
- Statically prove rc==1 → skip RC_IS_UNIQUE check, generate direct in-place mutation
- Typical: immediately after `new` or `clone`

**Pass 4: Drop Order Optimization**
- Reorder field releases in DROP: fields most likely to be REUSEd are released last
- Improves memory reuse hit rate

**Pass 5: Reuse Analysis**
- If DROP %old immediately followed by ALLOC %new with same size → replace with REUSE
- Skips dealloc+alloc, directly reuses memory address

### 3.5 Example: Pass Transformations

```
// Source
function main() {
    let hero = new Player("Alice", 100, 0, 0)
    damage(hero, 25)
    damage(hero, 10)
    print(hero.health)
}

// Initial PIR (after AST lowering)
%hero = ALLOC Player("Alice", 100, 0, 0)
RC_INC %hero                    // for damage param
CALL @damage(%hero, 25)
RC_DEC %hero                    // param done
RC_INC %hero                    // for second call
CALL @damage(%hero, 10)
RC_DEC %hero                    // param done
%hp = FIELD_GET %hero, health
CALL @print_int(%hp)
RC_DEC %hero                    // scope exit

// After Pass 2 (Move Analysis): RC_INC+RC_DEC pairs eliminated
%hero = ALLOC Player("Alice", 100, 0, 0)
CALL @damage(%hero, 25)
CALL @damage(%hero, 10)
%hp = FIELD_GET %hero, health
CALL @print_int(%hp)
RC_DEC %hero

// Final LLVM IR: 1 alloc, 0 rc_inc, 1 rc_dec (scope exit only)
```

## 4. Mutability Inference (Phase 2)

Compiler infers whether each function parameter is `mutated` or `readonly`. Not exposed to user syntax — optimization only.

**Analysis rules:** Parameter `p` is `mutated` if function body contains:
- `p.field = value` (direct field assignment)
- `p.field += value` (compound assignment)
- `p.field.subfield = value` (deep field assignment)
- `p.method_that_modifies()` (calls method that mutates)
- `other_function(p)` where other_function mutates corresponding parameter (recursive)

Otherwise `p` is `readonly`.

**Recursive/mutual recursion:** Fixed-point analysis. Initial assumption: all readonly. Iterate until convergence.

**Phase 1 behavior:** All object parameters treated as `mutated` (conservative but correct).

## 5. Bootstrap Strategy

**Plan A:** Seed compiler approach (no intermediate self-bootstrap).

1. **Freeze seed:** Current bin/ss is the seed compiler
2. **Build v1:** New compiler source uses OLD syntax (no field assign / clone). Seed compiles it. v1 supports new features for user code.
3. **Validate:** Extensive testing of new features (field const, clone, Perceus RC)
4. **Rewrite:** Compiler source migrated to new syntax (uses field assign, clone, etc.)
5. **Bootstrap:** v1 compiles rewritten source → v2. v2 compiles itself → v3. Verify v2 == v3.

**Key constraint:** Steps 2-3: compiler source does NOT use new features. New features only affect compiled output. Seed compiler can always compile the compiler.

## 6. Phase Plan

### Phase 1: Foundation (Minimum Viable)
- Parser: field-level `const`, field assignment (`obj.field = value`, nested), named parameter construction
- Checker: reject const field assignment (any depth, any context)
- Object layout: rc at offset 0, TypeInfo at offset 1
- TypeInfo generation: drop + deepClone + shallowClone per class
- Runtime: ss_retain, ss_release (generic via TypeInfo), ss_alloc (mimalloc), ss_dealloc, ss_shallow_copy
- Auto-generated .deepClone() / .shallowClone() per class
- Perceus IR: basic lowering (AST → PIR) + Liveness pass (rc_dec insertion)
- Collections: Array → List rename, Set (Map wrapper)
- All examples from spec must produce correct output

### Phase 2: Perceus Optimization
- Liveness analysis refinement
- Move optimization (eliminate redundant rc_inc/rc_dec pairs)
- Mutability inference (mutated/readonly parameter analysis)
- Uniqueness analysis (skip rc_is_unique when statically provable)
- const field optimization in clone (rc_inc instead of copy)

### Phase 3: Advanced Optimization
- Drop order optimization (reuse analysis)
- Memory reuse tokens (REUSE instruction)
- User-defined .deepClone()/.shallowClone() inlining
- Collection type specialization

### Phase 4: Language Completion
- Interface / trait (TypeInfo extended with method vtable)
- Generics
- Pattern matching
- FixedList / FixedMap / FixedSet
- Standard library
